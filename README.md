# RouteWolf

Выборочная маршрутизация для OpenWrt: выбранные домены и IP идут через VPN,
обычный интернет — через WAN. Поддерживаются WireGuard, AmneziaWG, OpenVPN;
есть экспериментальные режимы Sing-box/VLESS REALITY и Outline.

Стабильный выпуск: [v56](https://github.com/dagmagnat/RouteWolf/releases/tag/v56).
Архитектура, история, аудит и планы — в одном [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md).

## Установка

```sh
/bin/uclient-fetch -O - https://raw.githubusercontent.com/dagmagnat/RouteWolf/main/install.sh | sh
```

Нужны совместимые OpenWrt/fw4/nftables и пакеты для точной версии прошивки/ядра.
Поддерживаются `opkg` и `apk`. Если проверяемая HTTPS-загрузка не проходит,
проверьте время роутера и CA bundle.

## AmneziaWG: версия конфига и версия пакета

Перед вводом конфига можно выбрать автоматический режим (по умолчанию),
AWG 1.5, 2.0, 3.1 или старый 1.0. В автоматическом режиме сначала читается
конфиг, затем определяются требуемые возможности и устанавливаются пакеты.
Настройку можно предварительно задать через `ROUTEWOLF_AWG_MODE=auto`
или `1.5`, `2.0`, `3.1`, `1.0`.

Пакеты берутся из актуальных файлов официального релиза **для точной версии
OpenWrt, target/subtarget и архитектуры роутера**. Выбор старого формата конфига
не понижает версию пакета: пакет 3.1 может использовать конфиг 1.5 или 2.0;
отсутствующие новые параметры не заполняются произвольными значениями.
Уже установленные совместимые пакеты используются повторно. При несовместимости
они обновляются из того же релиза OpenWrt; `--reinstall` также обновляет пакеты.
Совместимость проверяется по установленному протокольному помощнику и `awg`,
а не по жёсткой таблице максимальных поколений для версий OpenWrt.

Параметры защиты заголовков, дополнительного паддинга, таймеров и переключатели
`RandomTrailers`/`DisableCookies` распознаются как профиль 3.1 и сохраняются в UCI.
`S3`/`S4` с ненулевыми значениями или диапазоны `H1`–`H4` требуют 2.0;
`I1`–`I5` без новых параметров — совместимости 1.5. Базовый конфиг без отличительных
полей неоднозначен между 1.0 и 1.5: установщик сообщает это и выбирает совместимость
1.5. Ручной выбор старого режима с новыми параметрами вызывает ошибку до применения
настроек. Устаревшие beta-параметры `Itime`/`J1`–`J3`, не поддерживаемые текущими
пакетами OpenWrt, не отбрасываются молча.

## AmneziaWG: загрузка IPK и установка с компьютера

OPKG-ветка скачивает IPK только для точной версии OpenWrt, архитектуры из
`opkg print-architecture` и target/subtarget. Используется общий загрузчик с
резервным переходом на curl/wget при отказе uclient-fetch. Если `github.com`
недоступен, установщик автоматически пробует официальный GitHub API и CDN
релиза. IPK проверяются как пакетные архивы; при загрузке через API также
проверяется SHA-256, если digest опубликован GitHub. Сторонние прокси не используются.
При ошибке выводятся URL и журнал `/tmp/routewolf-awg-install.log`. APK-файлы
в OPKG не передаются. Недоступность сети, лимит API или отсутствие пакетов
для конкретной прошивки всё ещё могут потребовать локальной установки.

Если на роутере недоступен GitHub, скачайте три IPK из официального релиза
[awg-openwrt](https://github.com/Slava-Shchipunov/awg-openwrt/releases) на ПК:
`kmod-amneziawg`, `amneziawg-tools`, `luci-proto-amneziawg` для своей платформы.
Перенесите их в `/tmp/awg-ipk`. Из папки распакованного проекта на роутере
запустите локальный установщик:

```sh
ROUTEWOLF_AWG_IPK_DIR=/tmp/awg-ipk sh ./install.sh
```

Выберите AmneziaWG. При заданной папке отсутствующий локальный IPK вызывает
понятную ошибку без попыток скачивания с GitHub. Зависимости устанавливаются
из настроенных репозиториев OpenWrt, поэтому доступ к ним всё ещё нужен.
OPKG проверяет зависимости и ABI ядра. Несовместимые пакеты принудительно
не устанавливаются. В старых релизах используется `luci-app-amneziawg`.

## Обновление установленного проекта

```sh
rw update
```

Если такой команды ещё нет:

```sh
/bin/uclient-fetch -O - https://raw.githubusercontent.com/dagmagnat/RouteWolf/main/update.sh | sh
```

Старые ссылки `getdomains-install.sh`, `getdomains-check.sh` и
`getdomains-uninstall.sh` сохранены как маленькие совместимые загрузчики.

## Ночные задания

| Время роутера | Действие |
|---|---|
| 02:00 ежедневно | Проверка списков доменов/IP |
| 03:00 ежедневно | Проверка опубликованного стабильного GitHub Release |

Неизменившиеся списки не перезапускают DNS/firewall. При той же версии архив
кода не скачивается. Изменения в `main` сами по себе не обновляют runtime
уже перешедших на v56 устройств.

Обновление проверяет SHA-256, состав архива и состояние после установки;
предыдущая версия сохраняется для отката. Ключи VPN и настройки WAN/DNS
сохраняются. При сбое загрузки остаются предыдущие рабочие файлы.

Нужно минимум 2 МиБ свободной flash и 8 МиБ доступной RAM. При меньшем резерве
обновление откладывается. Роутер с 16 МБ общей flash может обновлять скрипты
при достаточном свободном месте; установка Sing-box имеет отдельные требования.

## Управление и диагностика

```sh
rw status
rw diag
rw load
rw updates status
rw updates check
rw updates off
rw updates on
rw updates rollback
rw update
rw health
```

`off` отключает автообновление кода, но не списков. `health` проверяет и при
необходимости восстанавливает nft-наборы. Резервные копии содержат настройки
пользователя: не публикуйте их вместе с исходниками.

`rw update` проверяет стабильный релиз и списки (аналог `rw updates check`).
В v56 эта короткая команда ошибочно выводила Usage; исправление — v57.
Для разового обновления v56 используйте `rw updates check`, затем обычная
команда `rw update` снова работает. Ночные задания этой ошибкой не затронуты.

Для маршрутизации по доменам устройства должны использовать DNS роутера.
Проблемы upstream DNS и VPN проверяются отдельно. Google/Cloudflare
автоматически не подставляются; собственный DNS настраивается отдельно.
Fail-open сохраняет обычный WAN, но не обходит блокировку сервиса напрямую.

## Удаление

```sh
rw uninstall
```

Команда попросит ввести `DELETE`. Удаляет RouteWolf, его правила, списки,
вспомогательные скрипты и ночные задания. Работает без доступа к GitHub.
VPN-конфигурации, установленные пакеты и настройки WAN/LAN/DNS сохраняются.
Перед удалением создаётся приватная резервная копия в `/tmp`; после перезагрузки
она исчезнет, поэтому при необходимости скачайте её заранее.

`rw uninstall --help` показывает справку без удаления. `rw uninstall --purge`
также удаляет стандартные VPN-интерфейсы awg0/wg0 и конфиги OpenVPN проекта;
этот режим требует отдельного подтверждения и может отключить VPN.
Для автоматизации есть явный флаг `--yes`.

## Проверки для разработчика

```sh
python3 tools/build_release.py --check
docker build -t routewolf-tests -f tests/Dockerfile .
docker run --rm --network none --cap-add NET_ADMIN --memory=192m --cpus=1 \
  -v "$PWD:/work:ro" --entrypoint sh routewolf-tests -c \
  'touch /.routewolf-test-container; python3 -m unittest discover -s tests -p "test_*.py" -v'
```

Тесты создают одноразовые интерфейсы и firewall внутри контейнера.
Не запускайте тестовый Python-набор прямо на рабочем роутере.
