# RouteWolf

**RouteWolf управляет VPN-профилями, маршрутизацией и резервными подключениями на OpenWrt.**
Из LuCI можно выбрать, какой трафик идёт через туннель, назначить резервный профиль
и управлять библиотекой доменов и IP. Для подписок можно выбрать предпочитаемый сервер
и задать интервал обновления. Если основной профиль и резерв недоступны, новые соединения
идут через WAN.

## Возможности

- **Профили RouteWolf.** Единая настройка AmneziaWG, WireGuard, OpenVPN, sing-box, VLESS через Xray с XHTTP и Outline.
- **Маршрутизация.** Режим Full и два режима по спискам: выбранное через VPN или выбранное напрямую через WAN. Доступны библиотека RouteWolf, свои домены, IP, исключения и импорт GeoIP / GeoSite.
- **Управление.** Настройка через терминал или через **Службы → RouteWolf** в LuCI. В панели есть переключатель туннеля, статус связи и DNS для профиля.
- **Резерв.** В LuCI можно выбрать второй конфиг AmneziaWG или профиль другого протокола, например VLESS · Xray. Если основной туннель и резерв недоступны, работает WAN.

## Какой роутер подойдёт

| Флеш-память | Практический вариант |
| --- | --- |
| **16 МБ** | Начните с установки через терминал и WireGuard или AmneziaWG. LuCI и пакеты занимают место во флеш-памяти. Перед установкой проверьте свободное место командой `df -h /overlay`. |
| **128 МБ** | На более мощном роутере можно использовать LuCI, несколько профилей и подписки. Для Xray рекомендуется **от 256 МБ ОЗУ**. На роутерах со 128 МБ ОЗУ проверяйте запас памяти под нагрузкой. Для VLESS · Xray нужен `xray-core` с поддержкой TUN. |

Объём флеш-памяти — это место для прошивки и пакетов. Доступную оперативную память
можно посмотреть командой `free -m`. Для небольшого роутера два профиля AmneziaWG
используют один комплект пакетов протокола.

## Установка

```sh
/bin/uclient-fetch -O - https://raw.githubusercontent.com/dagmagnat/RouteWolf/main/install.sh | sh
```

В установщике выберите **Настроить в терминале** (по умолчанию), чтобы пройти
обычные шаги выбора протокола, импорта конфига и маршрутизации. Чтобы
настроить профиль из браузера, выберите **Установить для управления через LuCI**.
Панель появится в **Службы → RouteWolf**.

Нужны совместимые OpenWrt/fw4/nftables и пакеты для точной версии прошивки/ядра.
Поддерживаются `opkg` и `apk`. Если проверяемая HTTPS-загрузка не проходит,
проверьте время роутера и CA bundle.

Если `raw.githubusercontent.com` или загрузка архива с GitHub обрывается на
роутере, скачайте архив на компьютере, распакуйте его и скопируйте папку на
OpenWrt. В этой папке выполните `sh ./install.sh`. Этот способ обходится без
загрузки архива на роутере. Для установки пакетов и обновления списков по-прежнему
нужен доступ к их источникам либо заранее подготовленные файлы.

Установщик использует `opkg` на OpenWrt 23.05/24.10 и `apk` на 25.12.
При частичном сбое `opkg update` установка может продолжиться с индексами,
прошедшими проверку подписи, если в них есть нужные пакеты.

Установщик показывает объём RAM и доступное место до настройки туннеля.
При `MemTotal` ниже 64 МиБ доступны AmneziaWG, WireGuard и OpenVPN.
Для Sing-box и Outline также действуют требования к RAM и flash.

## Обновление установленного проекта

На действующем роутере используйте обновление, чтобы сохранить настройки.
Установленные v59, v58 и более ранние версии продолжают работать по своему
расписанию. Переход на v60 выполняется вручную на каждом роутере.

```sh
rw update
```

Если такой команды ещё нет:

```sh
/bin/uclient-fetch -O - https://raw.githubusercontent.com/dagmagnat/RouteWolf/main/update.sh | sh
```

Старые ссылки `getdomains-install.sh`, `getdomains-check.sh` и
`getdomains-uninstall.sh` сохранены как маленькие совместимые загрузчики.

### Переход на v60

Чтобы обновить скрипты и добавить панель к действующей установке:

```sh
/bin/uclient-fetch -O - https://raw.githubusercontent.com/dagmagnat/RouteWolf/main/update.sh | sh -s -- --luci
```

Чтобы обновить только скрипты до v60:

```sh
/bin/uclient-fetch -O - https://raw.githubusercontent.com/dagmagnat/RouteWolf/main/update.sh | sh -s -- --version 60
```

Выпуск [v60](https://github.com/dagmagnat/RouteWolf/releases/tag/v60) доступен
по явному выбору. Кнопка «Обновить проект», команда `rw update` и ночные
проверки используют канал [`Latest`](https://github.com/dagmagnat/RouteWolf/releases/latest).
Переход сохраняет активный профиль, режим маршрутизации, DNS, источники списков
и существующее расписание. Панель устанавливается только по выбору пользователя.
Команда с `--luci` также обновляет уже установленную панель на v60.
В «Профилях» выберите основной профиль и нажмите «Сохранить профили».
Кнопка рядом с вкладками запускает туннель или временно переводит трафик
на обычный WAN. Если сохранён только один профиль, его можно запустить сразу.

В поле «Маршрутизация» выберите «Списки напрямую, остальное через VPN»,
чтобы использовать библиотеку и свои списки для прямого выхода через WAN.
Снимите галочку «Использовать списки проекта», если нужны только свои записи.
После изменения режима сохраните и активируйте профиль. IPv6 идёт по этим
правилам при включённой поддержке IPv6 в RouteWolf и доступном IPv6 в туннеле.
При явном переходе на v60 манифесты и архивы скачиваются из исходного
репозитория через `raw.githubusercontent.com` и проверяются по SHA-256.
При ручной проверке обновлений в панели зеркало используется и при
недоступности `Latest`.

В панели можно задать дополнительные DNS для каждого профиля, сохраняя
резолверы провайдера. GeoSite и GeoIP импортируются по категориям, например
`geosite:youtube` и `geoip:telegram`, в собственные списки RouteWolf.
Эти списки применяются ко всем протоколам в выборочном режиме.
В «Списках» откройте «Импорт GeoIP / GeoSite», найдите категории по имени,
выберите нужные и нажмите «Добавить в список», затем «Применить списки».
Поиск и фильтр по типу сохраняют отмеченные категории, поэтому, например,
можно добавить GeoSite YouTube и GeoIP Telegram за один импорт.
Зелёный блок над кнопкой добавления показывает все отмеченные категории и их число.
«Списки по умолчанию» показывают библиотечные домены, IPv4 и IPv6 постранично.
Ручное редактирование доступно в «Своих записях». Исключения можно изменить
отдельной кнопкой рядом с просмотром библиотеки.
Поиск выполняется в браузере по встроенному каталогу. Роутер загружает
только выбранные наборы. Каталог обновляется командой `python tools/update_geo_catalog.py`.

В LuCI доступен профиль **VLESS · Xray**. Он принимает `vless://` и HTTPS-подписки
со списком VLESS-ссылок или клиентскими конфигурациями Xray JSON в открытом
тексте или Base64. Поддерживаются XHTTP,
обычный TCP, WebSocket, gRPC и HTTPUpgrade, а также параметры TLS и REALITY.
Профиль использует `xray-core` с поддержкой TUN из репозитория OpenWrt.
При первой активации панель перечислит недостающие пакеты. Профиль можно
выбрать основным в полном или выборочном режиме. Из JSON импортируются
исходящие VLESS-подключения. DNS и маршрутизацию задаёт RouteWolf.

## Ночные задания

| Время роутера | Действие |
|---|---|
| 02:00 ежедневно | Проверка списков доменов/IP |
| 03:00 ежедневно | Проверка опубликованного стабильного GitHub Release |

Неизменившиеся списки не перезапускают DNS/firewall. При той же версии архив
кода не скачивается. Изменения в `main` сами по себе не обновляют runtime
уже перешедших на v56 устройств.

Это расписание новой установки. При переходе на v60 сохраняются действующие
задания роутера, в том числе обновление только списков или проверка кода по субботам.

Обновление проверяет SHA-256, состав архива и состояние после установки;
предыдущая версия сохраняется для отката. Ключи VPN и настройки WAN/DNS
сохраняются. При сбое загрузки остаются предыдущие рабочие файлы.

Нужно минимум 2 МиБ свободной flash и 8 МиБ доступной RAM. При меньшем резерве
обновление откладывается. Роутер с 16 МБ общей flash может обновлять скрипты
при достаточном свободном месте; установка Sing-box имеет отдельные требования.

## AmneziaWG: версия конфига и версия пакета

Перед вводом конфига можно выбрать автоматический режим (по умолчанию),
AWG 1.5, 2.0, 3.1 или старый 1.0. В автоматическом режиме сначала читается
конфиг, затем определяются требуемые возможности и устанавливаются пакеты.
Настройку можно предварительно задать через `ROUTEWOLF_AWG_MODE=auto`
или `1.5`, `2.0`, `3.1`, `1.0`.

Пакеты берутся из актуальных файлов официального релиза **для точной версии
OpenWrt, target/subtarget и архитектуры роутера**. Выбор старого формата конфига
не понижает версию пакета: пакет 3.1 может использовать конфиг 1.5 или 2.0;
отсутствующие новые параметры не заполняются произвольными значениями.
Уже установленные совместимые пакеты используются повторно. При несовместимости
они обновляются из того же релиза OpenWrt; `--reinstall` также обновляет пакеты.
Совместимость проверяется по установленному протокольному помощнику и `awg`,
а не по жёсткой таблице максимальных поколений для версий OpenWrt.

Параметры защиты заголовков, дополнительного паддинга, таймеров и переключатели
`RandomTrailers`/`DisableCookies` распознаются как профиль 3.1 и сохраняются в UCI.
`S3`/`S4` с ненулевыми значениями или диапазоны `H1`–`H4` требуют 2.0;
`I1`–`I5` без новых параметров — совместимости 1.5. Базовый конфиг без отличительных
полей неоднозначен между 1.0 и 1.5: установщик сообщает это и выбирает совместимость
1.5. Ручной выбор старого режима с новыми параметрами вызывает ошибку до применения
настроек. Устаревшие beta-параметры `Itime`/`J1`–`J3`, не поддерживаемые текущими
пакетами OpenWrt, не отбрасываются молча.

## AmneziaWG: загрузка IPK и установка с компьютера

OPKG-ветка скачивает IPK только для точной версии OpenWrt, архитектуры из
`opkg print-architecture` и target/subtarget. Используется общий загрузчик с
резервным переходом на curl/wget при отказе uclient-fetch. Если `github.com`
недоступен, установщик автоматически пробует официальный GitHub API и CDN
релиза. IPK проверяются как пакетные архивы; при загрузке через API также
проверяется SHA-256, если digest опубликован GitHub. Сторонние прокси не используются.
При ошибке выводятся URL и журнал `/tmp/routewolf-awg-install.log`. APK-файлы
в OPKG не передаются. Недоступность сети, лимит API или отсутствие пакетов
для конкретной прошивки всё ещё могут потребовать локальной установки.

Если на роутере недоступен GitHub, скачайте три IPK из официального релиза
[awg-openwrt](https://github.com/Slava-Shchipunov/awg-openwrt/releases) на ПК:
`kmod-amneziawg`, `amneziawg-tools`, `luci-proto-amneziawg` для своей платформы.
Перенесите их в `/tmp/awg-ipk`. Из папки распакованного проекта на роутере
запустите локальный установщик:

```sh
ROUTEWOLF_AWG_IPK_DIR=/tmp/awg-ipk sh ./install.sh
```

Выберите AmneziaWG. При заданной папке отсутствующий локальный IPK вызывает
понятную ошибку без попыток скачивания с GitHub. Зависимости устанавливаются
из настроенных репозиториев OpenWrt, поэтому доступ к ним всё ещё нужен.
OPKG проверяет зависимости и ABI ядра. Несовместимые пакеты принудительно
не устанавливаются. В старых релизах используется `luci-app-amneziawg`.

## Подписки sing-box

В LuCI в разделе **Профили** можно назначить основной и резервный профили.
В резерве доступен любой добавленный протокол, в том числе
два профиля AmneziaWG с разными ключами. Для основной подписки сначала
проверяются её узлы по приоритету. При отказе основного профиля RouteWolf
проверяет резерв и переключает IPv4-трафик после успешной проверки HTTPS.
Если оба туннеля недоступны, трафик идёт через WAN. После восстановления
основного профиля маршрут возвращается на него. Для новых профилей по
умолчанию выбран запуск при загрузке. Два профиля AmneziaWG используют
один комплект пакетов. sing-box устанавливается при выборе профиля,
который его использует.

Если резерв VLESS · Xray уже работает, RouteWolf продолжает направлять через него трафик, пока проверяет восстановление основного AmneziaWG или WireGuard.

Для HTTPS-подписок sing-box и VLESS · Xray рядом с **Изменить** есть кнопка **Серверы**. Список показывает названия из подписки вместе с флагами и эмодзи. У узла без названия показываются адрес, порт и транспорт. Можно оставить автоматический выбор или назначить предпочитаемый сервер. Пока он недоступен, используется другой рабочий узел. После успешной проверки RouteWolf возвращается к выбранному серверу. В режиме JSON sing-box выбор действует внутри группы узла и сохраняет правила подписки. Если поставщик убрал выбранный сервер, RouteWolf возвращается к автоматическому выбору.

Режим подключается через **Sing-box → Подписка/JSON** при установке или явно выбранной замене туннеля. Ночные задания продолжают обновлять списки и проверять стабильный выпуск по прежним правилам. Действующая установка AmneziaWG продолжает использовать свою конфигурацию.

Вставьте HTTPS-ссылку подписки в установщик.
Поддерживаются списки ссылок VLESS, Trojan и Hysteria2 в обычном тексте и Base64,
а также совместимые JSON-профили Xray и sing-box. Приоритет серверов совпадает
с порядком в подписке.

- **Full** (по умолчанию) направляет интернет-трафик основной LAN через первый доступный сервер.
- **RouteWolf** направляет через подписку только трафик из списков доменов и IP проекта.
- **JSON** доступен, когда в подписке есть маршруты. Использует совместимые правила из профиля, включая стандартный выход и правила прямого подключения. Для каждого используемого тега прокси выбирается первый доступный узел этого тега.

JSON-импорт поддерживает, например, правила по доменам, адресам, CIDR, портам и сетевым протоколам. Доменные правила определяют имя по данным HTTP, TLS и QUIC, когда оно доступно. Если конфигурация требует внешних наборов правил, GeoIP/Geosite, Xray-балансировщика или несовместимых политик между профилями, установщик предложит вернуться к выбору режима. DNS, входящие интерфейсы и служебные настройки из JSON провайдера не переносятся.

В **LuCI → Службы → RouteWolf → Управление → Обновление подписок** можно выбрать проверку раз в 5, 10, 15, 30, 60 или 120 минут, задать свой интервал (5–1440 минут) или отключить автообновление. По умолчанию проверка выполняется раз в час. Кнопка **Проверить сейчас** ставит в очередь проверку текущей HTTPS-подписки даже при выключенном расписании. Настройка распространяется на sing-box, Xray и активный резерв с HTTPS-подпиской. Для отдельных ссылок на узлы обновление не предусмотрено.

Если обновление не скачалось или не прошло проверку, остаётся текущая конфигурация. При потере всех узлов новые соединения выходят через WAN. Маршрут через sing-box работает только при подтверждённой доступности и автоматически истекает за 18 секунд при зависании монитора. После восстановления прокси новые соединения снова используют подписку. При смене маршрута сайт или приложение может переподключиться.

Режим использует пакет sing-box с Clash API и модуль TUN. Установщик проверяет свободное место и RAM. На время работы отключается аппаратное и программное ускорение потоков fw4, если оно было включено. Иначе ускоренный трафик может миновать проверку маршрута. Это может снизить максимальную пропускную способность WAN.

- Состояние подписки — `/etc/routewolf-subscription/controller status`.
- События переключения — `logread -e routewolf-subscription`.
- Удаление подписки и восстановление ранее включённого ускорения — `/etc/routewolf-subscription/manage remove`. Выполните эту команду перед `rw uninstall`, чтобы удалить также настройки подписки.

## Управление и диагностика

| Задача | Команда |
| --- | --- |
| Посмотреть состояние туннеля | `rw status` |
| Собрать диагностику | `rw diag` |
| Посмотреть нагрузку | `rw load` |
| Проверить стабильное обновление и списки | `rw updates check` |
| Посмотреть канал и состояние обновлений | `rw updates status` |
| Отключить или включить автообновление кода | `rw updates off` / `rw updates on` |
| Проверить и восстановить наборы маршрутизации | `rw health` |
| Посмотреть отчёт по принятым и пропущенным записям | `rw lists report` |
| Проверить несколько адресов из списков | `rw lists check 5` |
| Откатить последнее обновление кода | `rw updates rollback` |

## Проверка списков (v59)

Перед применением RouteWolf проверяет каждую запись и включает в рабочие списки
только допустимые домены и IPv4/IPv6 CIDR. Исходные списки на GitHub не меняются:
ошибочные строки можно исправить по отчёту.

- Домены: отдельные метки 1–63 символа, полное имя до 253 символов, без пустых
  меток, подчёркиваний и дефисов по краям. IPv4 нельзя добавлять как домен.
  ASCII/punycode поддерживаются; Unicode IDN нужно заранее перевести в punycode.
  HTTP(S) URL, начальные `*.`/`.` и конечная точка нормализуются, регистр игнорируется.
  Принадлежность имени категории/сервису и существование домена этим не доказываются.
- IPv4: четыре десятичных октета 0–255, без неоднозначных ведущих нулей, маска
  0–32; без маски адрес становится `/32`. По умолчанию сети шире `/16` исключаются
  прежним ограничителем (`ROUTEWOLF_IPV4_MIN_PREFIX`). `/0`, loopback, link-local,
  unspecified, multicast и зарезервированный верхний диапазон не используются
  как VPN-назначения. Частные, CGN и документационные сети не удаляются вслепую:
  они могут быть намеренной частью пользовательской маршрутизации.
- IPv6: полная проверка hextet/compression, IPv4-embedded адресов и масок 0–128;
  без маски используется `/128`. Для защиты от слишком широкой маршрутизации
  допускаются префиксы `/32`–`/128`. Loopback, unspecified, link-local и multicast
  исключаются. Эквивалентные записи приводятся к единому виду.
- У CIDR должны быть нулевые host-биты. **`111.111.111.111/24` отклоняется**, в
  отчёте предлагается `111.111.111.0/24`: скрипт не расширяет адрес до целой сети
  молча. При этом **`111.111.111.111` — корректный IPv4**, он принимается как `/32`.
- Дубли и подсети, полностью покрытые уже указанной более широкой сетью,
  исключаются без расширения исходного набора адресов. Соседние сети автоматически
  не объединяются. Дубли доменов удаляются; вложенные домены сохраняются.
- Ошибочная запись не мешает принять корректные соседние записи. Если непустой
  вход не дал ни одной допустимой записи, сохраняются **все прежние списки**.
  Пустой файл/файл только с комментариями по-прежнему означает намеренное очищение.
- Посторонние директивы dnsmasq (`server=`, `conf-file=`, чужие nft-наборы)
  отклоняют всю транзакцию, сохраняя предыдущую рабочую конфигурацию.

После обновления выводятся счётчики. Подробности:

```sh
rw lists report
```

Отчёт содержит вид списка, номер строки, причину отказа, пример записи и итог
применения. Для экономии RAM сохраняется до 50 примеров на этап и не более
64 КиБ всего. Полные счётчики остаются в SUMMARY. Отчёт хранится в `/tmp`,
доступен root и исчезает после перезагрузки.

Для отдельной ограниченной проверки доступности:

```sh
rw lists check 5
```

Команда проверяет DNS для первых пяти уникальных доменов и ICMP для первых пяти
IPv4 `/32` (можно задать 1–20 на вид). Каждый запрос ограничен таймером.
**Никакие записи по результатам не удаляются**: timeout, фильтрация ICMP,
отсутствие A/AAAA, отказ DNS/VPN и выключенный сервер не доказывают ошибку записи.
Для целой CIDR-сети невозможно подтвердить доступность всех узлов одним запросом.
Это ручная диагностика, без дополнительного фонового сервиса и массового сканирования.

`off` отключает автообновление кода, но не списков. `health` проверяет и при
необходимости восстанавливает nft-наборы. Резервные копии содержат настройки
пользователя: не публикуйте их вместе с исходниками.

`rw update` проверяет стабильный релиз и списки (аналог `rw updates check`).
В v56 эта короткая команда ошибочно выводила Usage; исправление — v57.
Для разового обновления v56 используйте `rw updates check`, затем обычная
команда `rw update` снова работает. Ночные задания этой ошибкой не затронуты.

Для маршрутизации по доменам устройства должны использовать DNS роутера.
Проблемы upstream DNS и VPN проверяются отдельно. Google/Cloudflare
автоматически не подставляются; собственный DNS настраивается отдельно.
Fail-open сохраняет обычный WAN, но не обходит блокировку сервиса напрямую.

### Туннель активен, а YouTube или Telegram не открываются

В режиме по спискам проверьте, что нужные домены и IP входят в применённые
списки, а устройство использует DNS роутера. Для сравнения можно кратко
проверить тот же узел в режиме Full. Если проблема повторяется, сравните
доступность сервиса через другой узел и проверьте журнал командой
`logread -e routewolf-subscription`. Проверка состояния туннеля использует
тестовый HTTPS-запрос. Она подтверждает доступ к тестовому адресу, а UDP
и доступ к конкретному сервису проверяются отдельно. Для VLESS с gRPC
`serviceName` должен совпадать с настройкой сервера.

## Удаление

```sh
rw uninstall
```

Команда попросит ввести `DELETE`. Удаляет RouteWolf, его правила, списки,
вспомогательные скрипты и ночные задания. Убирает оставшиеся наборы nftables
RouteWolf после перезагрузки правил. Работает без доступа к GitHub.
VPN-конфигурации, установленные пакеты и настройки WAN/LAN/DNS сохраняются.
Перед удалением создаётся приватная резервная копия в `/tmp`; после перезагрузки
она исчезнет, поэтому при необходимости скачайте её заранее.

`rw uninstall --help` показывает справку без удаления. `rw uninstall --purge`
также удаляет стандартные VPN-интерфейсы awg0/wg0 и конфиги OpenVPN проекта;
этот режим требует отдельного подтверждения и может отключить VPN.
Для автоматизации есть явный флаг `--yes`.

Если в старой версии нет `rw uninstall`, скачайте удалятор и запустите его
из интерактивной SSH-сессии, чтобы он прочитал подтверждение `DELETE`:

```sh
/bin/uclient-fetch -O /tmp/routewolf-uninstall.sh https://raw.githubusercontent.com/dagmagnat/RouteWolf/main/routewolf-uninstall.sh &&
  sh /tmp/routewolf-uninstall.sh
```

Для удаления пункта RouteWolf из LuCI используется отдельный скрипт
[`luci-app-routewolf/uninstall.sh`](luci-app-routewolf/uninstall.sh).

## Проверки для разработчика

```sh
python3 tools/build_release.py --check
docker build -t routewolf-tests -f tests/Dockerfile .
docker run --rm --network none --cap-add NET_ADMIN --memory=192m --cpus=1 \
  -v "$PWD:/work:ro" --entrypoint sh routewolf-tests -c \
  'touch /.routewolf-test-container; python3 -m unittest discover -s tests -p "test_*.py" -v'
```

Тесты создают одноразовые интерфейсы и firewall внутри контейнера.
Не запускайте тестовый Python-набор прямо на рабочем роутере.

Архитектура и история проекта описаны в [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md).

## Происхождение и компоненты

Основой ранних версий RouteWolf был [itdoginfo/domain-routing-openwrt](https://github.com/itdoginfo/domain-routing-openwrt).
В RouteWolf появились панель LuCI, управление профилями и резервом, выбор серверов подписки,
библиотека списков и отдельный канал обновлений.

RouteWolf управляет подключениями через сторонние компоненты. Название в профиле
указывает, какой движок или протокол используется. Для подписок это
[sing-box](https://github.com/SagerNet/sing-box) и [Xray-core](https://github.com/XTLS/Xray-core).
