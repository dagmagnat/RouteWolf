# RouteWolf — контекст для продолжения работы

Этот файл заменяет PROJECT_NOTES, отдельные CHANGES и отчёт аудита.
README — пользовательская инструкция; здесь архитектура, решения и планы.
Не считать планы уже реализованными функциями.

## Требования владельца

- OpenWrt, в том числе Xiaomi AX3000T; поддерживать и роутеры с 16 МБ flash.
- Выбранные домены/IP идут через VPN, обычный интернет — через WAN.
- Отказ VPN не должен оставлять удалённого пользователя вообще без связи.
- Списки — ежедневно в **02:00**, код — ежедневно в **03:00**, по времени роутера.
  Не путать с «каждые два часа».
- Неизменившиеся списки не перезапускают DNS/firewall; та же версия не скачивается.
- При runtime-обновлении сохранять ключи, WAN и DNS пользователя.
- Владелец сообщает о недоступности Google/Cloudflare DNS у провайдеров.
  Не переключать на них автоматически. Собственный DNS — отдельный будущий тест.
- Нельзя намеренно отключать WAN/VPN на рабочем роутере оператора для тестов:
  через него идёт связь, восстановить на месте может быть некому.

## Архитектура

```text
LAN DNS -> dnsmasq -> vpn_domains -> mark 0x1 -> table 99/vpn -> VPN
CIDR lists --------> vpn_subnets ---^
ordinary traffic --------------------------------> main/WAN
```

Динамические DNS-наборы `vpn_domains`/`vpn_domains6` используют `dst_ip`.
CIDR-наборы `vpn_subnets`/`vpn_subnets6` используют `dst_net`/interval.
Правило fwmark 0x1/0x1 имеет priority 100. Не переносить общий default route в VPN
и не включать route_allowed_ips=1 без отдельного решения владельца.

Есть WireGuard, AWG, OpenVPN и экспериментальные Sing-box/VLESS REALITY/Outline.
Полной поддержки любых подписок, XHTTP/gRPC и автовыбора пока нет.

## Источники истины

- `install.sh`: bootstrap/интерактивная установка; `update.sh`: совместимый
  вход для установленного проекта через стабильный runtime-канал.
- `routewolf-install.sh`: установщик и literal heredoc для большинства
  генерируемых /usr/sbin, init/hotplug-скриптов.
- `runtime/*.sh`: канонические fetch/update/reliability helpers; имеют приоритет
  перед одноимённым heredoc при сборке релиза.
- `lists/*` и profiles/lite — данные маршрутизации. Служебные/локальные диапазоны
  не удалять вслепую. Списки отделены от версии кода.
- `tools/build_release.py`: сборка и проверка ограниченного runtime-архива.
- `releases/stable.manifest`: bridge для v55; архивы v55/v56 — опубликованные
  данные, v55 также нужен отрицательному контрольному тесту. Это не мусор.
- `tests/test_stability.py`, `tests/Dockerfile`, `.github/workflows/stability.yml`:
  проверки исходников и настоящих nftables/ip rules в изолированной namespace.
- `getdomains-*.sh`: маленькие aliases старых публичных команд; не удалять URL
  без миграции. `routewolf-check.sh` вызывает установленный `rw diag`.
- uninstall/cleanup — отдельные ручные операции, не часть автообновления.
- `/etc/routewolf` и конфиги VPN содержат пользовательские данные; не копировать
  в GitHub. Snapshot: `/etc/routewolf/rollback/runtime.tgz`.

Функция внутри `cat << 'EOF' > /usr/sbin/rw` принадлежит будущему файлу rw,
а не namespace установщика. Раньше это ломало DCO. Проверять реальные границы
heredoc и запускать нужный слой; одного sh -n недостаточно.

## История и проверенные исправления

**v58-uninstall-command**: `rw uninstall` / `rw remove` вызывают локальный
удалятор, `--help` не меняет систему. Требуется DELETE или явный --yes.
По умолчанию остаются VPN-конфиги, пакеты, WAN/LAN/DNS и общие VPN-зоны;
--purge дополнительно удаляет awg0/wg0 и известные OpenVPN-конфиги проекта.
Удаляются в том числе новые ночные cron, stable-update/reliability/fetch helpers.
Источник удалятора — корневой routewolf-uninstall.sh: его копирует установщик
и использует сборщик runtime. Сеть для удаления не требуется. Перед изменениями
проверяются UCI/locks, сохраняется приватный backup в RAM. На рабочем роутере
проверять только --help и отмену, настоящее удаление — в изолированном fixture.

**v57-command-compat**: исправлен публичный `rw update`: перед вызовом helper
удаляется имя подкоманды, а helper также принимает прежний префикс `update`
для совместимости с уже установленным rw v56. Аргументы (включая пути с
пробелами) и код выхода сохраняются. Добавлены исполняемые регрессионные тесты
нового rw и реального rw из архива v56. Для получения исправления на v56:
`rw updates check`; ночная проверка кода в 03:00 тоже получает новый релиз.
Содержимое опубликованных v55/v56 не переписывать. DNS, списки и маршруты
этим исправлением не меняются. Числовой v57 сохраняет совместимость текущего
обновлятора; переход на SemVer остаётся отдельной задачей.

До v55 исправлялись OpenVPN gateway при нуле в октете/смене подсети, маршрут
point-to-point без выдуманного gateway, дубли policy rules, MTU/TV/IPv4,
opkg/apk и AWG-пакеты для точной прошивки. На части OpenVPN DCO-сборок наблюдалась
потеря ключа при ротации: сохранять осознанный выбор пользователя, не объявлять
все прошивки одинаковыми. Ночной update.sh --auto прежде обновлял только списки;
старейшие getdomains-only установки не загружают код вообще.

В v55 зафиксировано: DNS отвечал, но существующий interval vpn_domains отвергал
даже прямую запись с ENOENT. Рестарт DNS не помог; host-address набор восстановил
YouTube, владелец подтвердил видео. Это не доказательство причины всех похожих
отказов у других пользователей. Добавлены nft write probe, SHA-256, snapshots,
rollback и pending. Двухчасовое расписание оказалось неверным и исправлено в v56.

**v56**: [Release](https://github.com/dagmagnat/RouteWolf/releases/tag/v56),
проверенный commit `976dc4581eb2f728b85f5f9b2e4c9c9be3fafdbb`.
51 тест прошёл в контейнере и GitHub Actions. На AX3000T установка и проверка
Release прошли; SHA WAN/DHCP/DNS/туннеля и main route сохранились, запрос через
AWG работает, одинаковые списки не перезапускают DNS. Рабочий WAN не отключали.

Исправления аудита v56:

1. Отдельные jobs 02:00/03:00, без подмены timezone.
2. `releases/latest/download/stable.manifest`; архив из точного
   `releases/download/v<номер>/routewolf-v<номер>.tar.gz`, без смешивания latest.
3. Watchdog мог повторно добавить policy route к UP, но недоступному VPN.
   Это воспроизведено на v55; обычный WAN и тогда оставался доступен.
   Теперь unhealthy-маркер в RAM снимается после успешной проверки.
4. Pending сохраняется при ошибке rollback; recovery доступен при следующем
   запуске и boot init. Snapshot имеет checksum; старый v55 совместим.
5. Проверка TLS, ограничение загрузки/распаковки; до staging требуется минимум
   2 МиБ free flash и 8 МиБ available RAM. Сценарий 5 МиБ free прошёл тест.
6. URL, вставленный администратором, экранируется в sourced shell-конфиге.
   Это не unauthenticated remote exploit.
7. Domain list не задаёт произвольный server= и не пополняет чужие ACL-наборы;
   неизвестные директивы отклоняются с сохранением прежнего cache.

Архив v56: 25 283 байта, 30 скриптов, без firmware/kernel/packages/keys.
SHA-256: `cb59b749ff5b2fc793215d09b4d70799a675849c6f350dc7124ebb6c3d1bf56c`.

## Выпуск следующего исправления

Повысить version и PROJECT_VERSION, собрать и проверить архив; CI на ветке,
при необходимости положительный canary без отключения связи; draft Release
для точного проверенного commit. Загрузить manifest, runtime и updater, сверить
SHA и только затем публиковать стабильный Release. Bridge в main не должен
указывать на непроверенный выпуск. Сам commit в main не является релизом для v56.

Не перезаписывать опубликованные версии/теги. Gzip может различаться между
Windows/Linux/zlib: проверять точное содержимое и SHA через --check, а не
перепаковывать хороший архив другим компрессором.

## Ограничения

DNS, nftset, VPN и видеопоток проверяются отдельно. Недоступный upstream DNS
не доказывает блокировку VPN IP. Fail-open сохраняет обычный WAN, но напрямую
заблокированный сервис может оставаться недоступен.

Нет гарантии исправления любого драйвера/ядра/внешней блокировки. Неизвестные
firewall-конструкции, несовместимые tools или нехватка ресурсов требуют остановки
обновления, а не принудительной переделки настроек. 5 МиБ free — тестовый сценарий,
не натурная проверка каждой 16-МБ модели. Journal уменьшает риск сбоя питания,
но не гарантирует исправность flash. SHA проверяется относительно manifest по
HTTPS; отдельной offline-подписи нет, GitHub владельца — доверенная граница.

## Очистка после v56

Удалены неподключённые Node/Nexus app.js/EJS/CSS, старый Ansible-role с отсутствующими
templates, его тесты, дубли README и разрозненная история. Перед удалением создан
локальный ZIP. Рабочие installers/runtime, lists, releases, тесты и CI сохранены.
История Git и опубликованные теги не переписаны.

## Идеи владельца — ещё не задача на реализацию

- Расширить Sing-box, VLESS/REALITY, XHTTP/gRPC и поддержку подписок.
- Выбирать доступный сервер, позже продумать failover/нагрузку.
- LuCI-интерфейс: статусы, списки, обновления, диагностика, управление без CLI.
  Старые Node/Nexus-файлы не были готовым LuCI-интерфейсом RouteWolf.
- Собственный DNS отдельно спроектировать и проверить.
- Предложен SemVer: 1.0.0, 1.0.1 (bugfix), 1.1.0 (features), 2.0.0 (breaking).
  Это пока обсуждение: установленные роутеры читают числовой manifest/tag v55/v56.
  Нужна совместимая миграция, а не простое переименование тегов. Компоненты не
  десятичные дроби; 100-й patch не требует автоматически следующего major.
