# v56 — ночное расписание и GitHub Releases

## Ежедневно, по часовому поясу роутера

- **02:00 — только списки доменов/IP.** Если содержимое не изменилось, DNS и
  firewall не перезапускаются, cache во flash не переписывается.
- **03:00 — только версия проекта.** Проверяется последний опубликованный
  стабильный GitHub Release. При той же версии архив не скачивается, скрипты
  не заменяются. Черновики и prerelease не являются каналом обновления.
- Проверка nftset каждые пять минут остаётся отдельной лёгкой задачей.

Это исправляет неверно установленное в v55 двухчасовое расписание. После
успешного перехода старые задания RouteWolf заменяются, остальные cron-задачи
пользователя сохраняются.

## Стабильные релизы

В GitHub Release публикуются три файла:

```text
stable.manifest
routewolf-v56.tar.gz
routewolf-stable-update.sh
```

Версия берётся из `releases/latest/download/stable.manifest`, а архив — из
`releases/download/v<номер>/routewolf-v<номер>.tar.gz`. Это исключает смешивание
файлов разных версий при обновлении latest. Все загрузки проверяют HTTPS и SHA-256.
Сам по себе commit в `main` не обновляет уже перешедшие на v56 роутеры.

Старые загрузчики v55, использующие `main/releases/stable.manifest`, сохраняют
совместимость для перехода. Эту bridge-копию публикуют только после проверки и
публикации соответствующего Release. Старые getdomains-only установки без
загрузки кода требуют одного ручного обновления.

## Небольшие роутеры

Архив содержит только 30 runtime-скриптов, без прошивки, ядра, пакетов и ключей.
Перед скачиванием/распаковкой проверяются минимум **2 МиБ свободной flash и
8 МиБ доступной RAM**. При нехватке ресурса текущая версия сохраняется.
Загрузки ограничены по размеру, размер распакованных файлов также проверяется.
Наличие 16 МБ общей flash само по себе не запрещает обновление: важен фактический
свободный объём. Пять МиБ свободного места проходят проверку для этого релиза.

## Исправления аудита

Подробности и границы проверки: [AUDIT-v56.md](AUDIT-v56.md).

- Сохранение обычного WAN при отказе VPN остаётся основным поведением.
- Исправлен крайний сценарий: после неудачного теста watchdog мог заново
  добавить маршрут к всё ещё UP, но недоступному VPN. Теперь недоступность
  запоминается в RAM; только успешная проверка разрешает восстановить этот маршрут.
- Перезапуск здорового туннеля только из-за загрузки роутера больше не нужен.
- Маркер незавершённого обновления не удаляется при неудачном откате.
  Восстановление возможно при следующем запуске, в том числе из boot init.
- Добавлена проверка резервной копии; старые snapshots v55 совместимы.
- URL собственных списков экранируются при сохранении shell-конфигурации.
- Данные списков больше не могут задавать произвольный DNS-сервер или заполнять
  чужие firewall-наборы. Старые пользовательские списки с такими директивами
  будут отклонены с сохранением предыдущего cache, а не молча применены.

## Ручные команды

```sh
rw update
rw updates status
rw updates check
rw updates rollback
```

Старая команда загрузки `update.sh` сохранена. На уже настроенном RouteWolf она
использует стабильный runtime-канал, а не переустановку VPN. Для отдельной новой
настройки/замены туннеля остаётся интерактивный `install.sh`.

DNS-провайдеры, конфиг туннеля и WAN при runtime-обновлении сохраняются. Google и
Cloudflare не подставляются автоматически. Собственный DNS настраивается отдельно.
